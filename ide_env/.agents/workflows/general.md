description: Implement Workflow
---

Understand:

* what needs to be implemented,
* expected behavior,
* requirements,
* constraints,
* acceptance criteria,
* and scope.

Do not begin significant implementation based on unclear assumptions.

## Step 2: Inspect the Existing Codebase

Before modifying existing code, inspect relevant:

* files,
* modules,
* architecture,
* interfaces,
* dependencies,
* configuration,
* tests,
* and project conventions.

Understand how the new implementation fits into the existing system.

## Step 3: Identify Impact

Determine:

* files to modify,
* files to create,
* components affected,
* interfaces affected,
* data flow changes,
* dependency changes,
* possible regressions,
* security implications,
* and documentation updates.

## Step 4: Plan the Implementation

Define the implementation approach before significant code changes.

Keep the design proportional to the task.

Prefer the simplest approach that satisfies the actual requirements.

## Step 5: Implement

Write code according to the applicable:

* Global Rules,
* Workspace Rules,
* project conventions,
* architecture,
* coding standards,
* security requirements,
* and technology-specific best practices.

Write code that is:

* correct,
* readable,
* maintainable,
* idiomatic,
* appropriately modular,
* and appropriate for the project's complexity.

Avoid unnecessary duplication, abstraction, and overengineering.

## Step 6: Review Related Areas

After implementation, inspect relevant:

* affected files,
* integrations,
* interfaces,
* error handling,
* configuration,
* tests,
* and related code paths.

Check whether the implementation creates unintended side effects.

## Step 7: Verify

Run appropriate verification when available, such as:

* builds,
* tests,
* linters,
* type checking,
* static analysis,
* manual testing,
* integration testing,
* or security checks.

Consider relevant edge cases and failure scenarios.

## Step 8: Check for Regression

Verify that related functionality has not been unintentionally broken.

Inspect affected components beyond the immediately modified file when relevant.

## Step 9: Summarize

After significant implementation, summarize:

* what was implemented,
* important design decisions,
* affected areas,
* verification performed,
* known limitations,
* and recommended next steps.

Do not claim successful testing or verification unless it actually occurred.
