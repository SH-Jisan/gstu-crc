# Technical Research Skill

Activate this skill when evaluating third-party dependencies, API changes, migration paths, architectural paradigms, or ecosystem tools.

## 1. Research Methodology Protocol
- **Focused Scope**: Define the exact technical decision to be made, operational constraints, and non-negotiable criteria.
- **Authoritative Hierarchy**: Prioritize information sources strictly:
  1. Official specifications, primary documentation, and release changelogs.
  2. Maintainer blog posts, RFCs, and security advisories (CVE databases).
  3. Industry benchmarks with reproducible testing harnesses.
  4. Community forums (StackOverflow, Reddit) only for qualitative sentiment or known edge-case bug reports.
- **Freshness Verification**: Verify release dates, LTS support windows, active maintenance status, and deprecated API notices.

## 2. Comparative Decision Matrix
Compare candidate technologies across standardized vectors:
- **Functional Completeness**: Does it natively solve the requirement?
- **Performance & Overhead**: Memory footprint, latency overhead, bundle size impact.
- **Ecosystem Health**: Community activity, issue response velocity, commercial backing, documentation quality.
- **Security & License**: Vulnerability history, CVE remediation speed, license compatibility (MIT, Apache 2.0 vs. AGPL).
- **Migration & Lock-In**: Ease of integration and eventual exit cost.

## 3. Recommendation Delivery
- Deliver a clear, evidence-backed choice.
- Explicitly state key trade-offs and scenarios where an alternative candidate should be chosen instead.
